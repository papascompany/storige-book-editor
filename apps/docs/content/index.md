# Storige 파트너 문서

Storige 는 단일 인쇄 백엔드로서 여러 외부 파트너를 호스팅합니다. 이 사이트는
연동에 필요한 계약(엔드포인트·인증·에러·웹훅)을 발행하는 채널이며, 규범 서술의
정본은 [연동 가이드](/guide/) 입니다.

## 어디부터 읽을 것인가 — 시나리오 3종

아래 셋 중 지금 하려는 일에 가장 가까운 하나로 들어가세요. 세 시나리오 모두
[공통 기반](/guide/common/) 의 인증·한도·에러 계약 위에서 돕니다.

### ① PDF 를 내가 만든다 — 업로드 주문

자체 편집기나 렌더러로 표지·내지 PDF 를 이미 만들 수 있고, Storige 의 인쇄 검증·
합성·산출만 필요한 경우입니다.

→ [유형 1 — v1 도서 경로](/guide/self-editor/#2-0) 에서 여정 전체(판형 확인 → 도서
생성 → 자산 투입 → 최종화 → PDF 수령)를 보세요. 기존 파트너가 쓰는 레거시 워커 잡
경로는 [같은 페이지의 2.1 이후](/guide/self-editor/#2-1) 에 있습니다.

### ② 편집 UI 를 Storige 에 맡긴다 — 임베드 세션 승격

고객이 Storige 편집기(`/embed`)에서 편집하고, 완료된 세션을 파트너 서버가 주문으로
승격하는 경우입니다.

→ iframe 임베드와 이벤트 수신은 [유형 2](/guide/embed/), 완료 세션을 도서로 올리는
승격 계약(`EDITOR_SESSION`)은 [1.7 의 승격 항목](/guide/common/#1-7) 을 보세요.

### ③ 완료 통지를 비동기로 받는다 — 웹훅 수신

①·② **모두**에 필요합니다. 최종화는 비동기이고 폴링은 백스톱이지 정본 알림 경로가
아닙니다.

→ [5.2 Webhook 서명 검증](/reference/#5-2) 에 발신 경로 2종·서명·중복 배달·응답
규약이 있습니다.

## 시작 전에 알아 둘 것

- **파트너 셀프서비스 등록은 없습니다.** 테넌트(Site) 생성과 키 발급은 Storige
  운영자가 수행하며, 요청 양식은 [1.1 온보딩 절차](/guide/common/#1-1) 에 있습니다.
- **실행 예제 3종**(PDF 업로드 주문 · 임베드 세션 승격 · 웹훅 수신)이 레포
  `examples/` 에 있습니다. 라이브 키 없이 도는 오프라인 검증을 포함하지만,
  실 서버 대상 스모크는 파트너 환경에서 별도로 해야 합니다.
- **TypeScript SDK 는 아직 npm 에 배포돼 있지 않습니다**(사내 배포 검토 중).
  배포 전까지는 문서의 HTTP 계약을 직접 구현하거나 위 예제를 참고하세요.
