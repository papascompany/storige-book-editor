Q1
표지는 표지펼침면인가, 표지3분할인가?
표지펼침면(책등 고정, flat-spread) — 통짜 1장. 내지 수가 늘어도 책등 파일을 키우지 않음.
표지3분할(책등 가변, full / IDML flat-spine) — 뒷/등/앞. 등 구역만 내지 수를 따름.
Q2
내지는 낱장인가, 펼침면인가? (상품이 정한다)
내지낱장 = page · 내지 1, 내지 2는 다른 시드 가능.
내지펼침면 = regionScope:'inner' · 캔버스 1장=좌+우. 포토북 전용이 아니다.
Q3
기성·페브릭인가? (표지 구조와 별개)
소재를 배경으로 깔고 고객 잠금이면 coverEditable=false. 보통 표지펼침면과 짝. 후가공 on/off 는 템플릿셋.
가장 흔한 오해: "가변이면 책등 폭을 안 넣어도 된다" — 반대다. 가변 템플릿도 기준 책등 폭이 필수다(Admin 라벨 initialSpineWidthMm). 이 값이 편집 시작 레이아웃이자 각 객체가 어느 면에 속하는지 판정하는 기준이 된다. 비워두면 7.5mm 가 들어간다.

⚠ 블리드 단위 — 가장 많이 틀리는 곳

cutSizeMm 는 "사방 도련"이 아니라 양변 합이다. 사방 3mm 도련을 원하면 cutSizeMm: 6 을 넣어야 한다. 템플릿셋의 bleedMm(사방)과 단위가 다르다 — 두 값을 같게 넣으면 도련이 절반이 된다.

안전한 운용: 템플릿셋에서 bleedMm > 0 과 함께 "재단선 마커 표기"를 켜라. 게이트가 켜지면 편집기가 bleedMm × 2 로 cutSizeMm 을 덮어써 자동 정합된다. 블리드만 넣고 마커를 안 켜면 고객 화면과 PDF에 블리드가 0으로 나간다.
안전선(safeSizeMm) 주의: 책등 세이프존 가이드는 실제보다 2배 보수적으로 표시된다. 화면 가이드가 빡빡해 보여도 실제 여유는 그보다 크다 — 다만 가이드 안쪽에 배치하는 것을 기준으로 삼는 편이 안전하다.

2 표지는 항상 캔버스 1장 — 안의 구조가 다르다

앞·등·뒤를 템플릿 파일 세 개로 나누지 않는다(type=cover/spine 레거시). 캔버스는 하나다. 그 안을 표지펼침면(통짜)으로 둘지, 표지3분할(뒷/등/앞 구역)로 둘지가 갈린다. 3분할의 영역 순서는 좌→우 고정이다.

책등spine

앞날개front-wing

폭이 0 이하인 영역은 통째로 사라진다. 날개를 끄거나 책등이 0이면 그 영역의 경계선·가이드·치수라벨이 아예 생성되지 않는다. "날개를 껐는데 가이드가 남았다"는 상황은 정상이 아니다.

제작 규칙

  • 기준 책등 폭은 중간값으로. 최소/최대 페이지의 중간 정도. 극단값이면 반대쪽에서 재배치 폭이 커진다.
  • 한 요소는 한 면 안에. 면을 가로지르는 띠·제목 박스는 면별로 잘라서 각각 배치한다.
  • 앞·뒤표지 요소는 책등 경계에서 최소 safeSizeMm 이상 띄운다. 경계에 딱 붙이면 책등이 좁아질 때 이탈 판정이 난다.
  • 뒤표지 객체도 반드시 앵커를 갖게 하라. 앵커 없이 두면 책등이 커질 때 책등 쪽으로 드리프트한다.
  • 책등 글자는 예상 최소 페이지 기준 폭에서도 들어가는 크기로. 무선 3mm 미만 상품에는 책등 글자를 넣지 않는다.
  • conversionMode 는 full 또는 flat-spine 만. flat-spread 는 가변이 차단된다.

양장 / 싸바리 — 기하가 두 벌이라 주의

하드커버 표지 기하가 코드에 두 벌 있고 서로 정합이 보장돼 있지 않다. 편집기 출력은 caseBind 모델을, 워커 표지 검증은 별도 상수 모델(각 면 +8mm / 전개 +40mm)을 쓴다.
권장: 하드커버 템플릿셋의 caseBind 3필드(합지·접힘·wrap) 합을 28mm 기준(±1mm) 으로 잡아라. 예: 합지 2.5 + 접힘 17.5 + wrap 8 = 28. 다르게 잡아야 한다면 검증 허용오차를 함께 조정해야 한다.

5 책등 폭 공식

제본 코드별로 공식이 완전히 다르다. 산술 정본은 packages/types/src/spine-calc.ts 한 곳이고 API·워커·골든 스펙이 모두 이 모듈만 쓴다.

무선 perfect v2

홀수면 +1 보정 후
round2(유효페이지 × mm/페이지)

제본 마진 가산 없음. 소수 유지(정수화 금지).
용지 컬럼: thicknessPerPageMm

양장 hardcover v2

max( 4 + ceil(p/2 × mm/장), 8 )

결과는 정수 mm, 최소 8mm.
4 = 마닐라 합지 상수.
용지 컬럼: thicknessPerSheetMm

그 외 v1 레거시

(p ÷ 2) × 두께 + 제본마진

중철·스프링, 그리고 v2 두께가 없는 지종이 여기로 조용히 폴백.
두 두께표의 단위가 다르다. 무선표 = mm/페이지, 양장표 = mm/장(페이지 2장). 같은 지종이면 perPage × 2 ≒ perSheet 여야 한다. 섞어 넣으면 책등이 정확히 2배 또는 절반으로 틀어진다.
formulaVersion 을 확인하라. 응답의 spineWidth 만 보면 v2 두께가 없는 지종에서 옛 v1 값이 조용히 돌아온다. 상품에 연결할 지종은 GET /products/spine/paper-types 에서 해당 두께 컬럼이 채워진 것만 고르라.
※ 계산 API는 성공 시 201 을 반환한다 — 200 고정으로 처리하지 말 것. 인증 없이 호출 가능(@Public).

5-1. 표지 날개 — 여기만 "주문 옵션이 템플릿보다 우선"

판형·책등은 템플릿/템플릿셋이 권위인데, 날개만 반대다. 같은 표지 템플릿으로 날개 상품과 비날개 상품을 함께 운영하기 위해 2026-08-03 신설됐다.

전달값결과
미전달템플릿 spec 값 그대로 (기존 동작 불변)
wingEnabled=false폭과 무관하게 끔
wingEnabled=true + 유효 폭켬
wingEnabled=true + 폭 없음거부(끔) — 폭 0 영역은 렌더에서 skip 돼 "켰는데 안 보임"이 되므로
폭만 전달템플릿의 사용여부 유지 + 폭만 교체
날개를 주입하면 펼침면 총폭이 바뀐다 — 저장된 표지 아트워크는 절대좌표라 그대로 두면 영역 대비 어긋난다. 편집기가 책등과 동일한 재배치 로직으로 자동 보정하지만, 그래서 §3·§6 의 앵커 규칙(객체를 한 번 움직여 메타 확정)이 날개 상품에서 특히 중요하다. 좌우 동일 폭 단일 모델이라 앞/뒤 비대칭 날개는 지원하지 않는다.

객체 타입책등이 넓어지면이유

여기서 나오는 실무 규칙
  • 책등 제목은 반드시 텍스트 객체로. 이미지로 얹으면 책등 폭에 따라 늘어난다. 반대로 책등 배경 띠는 이미지가 유리하다.
  • 책등 로고+텍스트는 하나의 그룹으로 묶어라. 텍스트 포함 그룹은 전체가 스케일 금지가 되어 비율이 유지된다.
  • 책등 텍스트가 여러 개(제목·저자·출판사)면 각각 앵커를 갖게 하라. yNorm 이 다르면 책등이 늘어나도 상하 배치가 보존된다. 앵커가 없으면 전부 면 중앙에 적층된다.
  • 펼침면 전폭 배경은 full 템플릿에 그냥 넣지 마라. flat-spine 3분할로 등록하거나, 면별로 잘라 각 면에 배치한다.
  • "잠금"은 가변 방어가 아니다. 절대 안 움직여야 하는 아트워크는 flat-spine 산출물로 만들거나 flat-spread 로 등록하라. 잠금은 고객 실수 방지용이다.
  • 책등이 잘못 반영되면 Ctrl+Z 가 아니라 입력값을 되돌려라. 내지 수·용지·제본을 되돌리면 재계산된다.

7 내지 — 내지낱장 vs 내지펼침면

페이지 수량 규칙

  • canAddPage — 고객이 내지를 추가할 수 있는지. 이게 true 여야 책등 가변이 의미를 갖는다.
  • pageCountRange 는 [최소, 최대] 2원소 클램프다. [8,24,48] 처럼 이산 목록을 넣어도 중간값은 어디서도 강제되지 않는다. "8/24/48 중 택1" 같은 제약이 필요하면 파트너 주문 화면에서 막아야 한다.
  • 제본 배수·최소 페이지는 경고일 뿐 차단이 아니다(§5). 상품 정책으로 막으려면 pageCountRange 와 파트너 주문 옵션으로 이중 관리하라.
  • 포토북 최소 제작 페이지를 실제로 막으려면 가격 설정의 minPages 만으로는 부족하다 — pageCountRange 최소값에도 같은 수치를 넣어라.
  • pageCountRange 는 언제나 물리 페이지 기준이다. 펼침면 세트는 캔버스 1장 = 2페이지라 [8,40] 이면 펼침면 4~20장이 된다. 캔버스 수로 착각해 넣으면 상·하한이 절반으로 걸린다.

8 등록 절차와 판형 규약

판형 규약 — 실사고가 있었던 지점. templateSet.width/height 는 내지 재단 사이즈다. 표지 한 면 크기가 아니다. 표지 치수는 오직 spreadConfig.spec 에서만 표현한다. (실사고: 가로 A4 하드커버 세트를 301×214 로 등록 → 297×210 으로 교정)
내지 템플릿 캔버스는 세트 판형과 ±0.01mm 일치해야 한다 — 방향(가로/세로) 포함. Admin 후보 목록은 작업사이즈(재단+2×블리드) 템플릿도 선택 가능하게 보여주지만 서버는 재단 정확 일치만 통과시킨다. 저장 전 "치수 정합" 경고 배너가 0 인지 반드시 확인하라. (spread 템플릿은 예외 — spec 만 맞으면 되고 width/height 는 서버가 계산한다.)

IDML 원고 규격 — 이걸 어기면 스펙이 잘못 유도된다

  • 표지는 정확히 5페이지 [뒷날개·뒤표지·책등·앞표지·앞날개] 또는 3페이지 [뒤표지·책등·앞표지].
  • 책등이 항상 가장 좁은 페이지여야 한다. 날개 폭은 반드시 책등보다 크게.
  • 링크 이미지를 같이 올려라. 안 올리면 회색 박스가 된다. 매칭은 파일명 기준이라 이름을 바꾸면 실패한다. TIFF/EPS/PDF/AI 는 디코드 불가 → JPG/PNG 로 변환.
  • 회전된 배치 이미지 금지 — 회전이 필요하면 미리 회전된 비트맵으로 만들어 배치.
  • 미등록 폰트는 먼저 시딩(TTF/OTF/WOFF2. woff1 은 불가). 등록 이름은 변환기가 읽은 표기 그대로.
  • 장평·점선/특수 스트로크는 패스로 변환해서 넘긴다.
  • 변환 미리보기의 "감지된 사양"(표지폭·책등·날개·총폭)을 반드시 육안 대조하라.

9 함정 체크리스트

치수·단위

  • cutSizeMm 에 사방 도련 × 2 를 넣었는가(3mm → 6). 세트 bleedMm 과 단위가 다르다.
  • 블리드를 쓴다면 재단선 마커 표기도 켰는가. 안 켜면 PDF 블리드가 0이다.
  • 세트 판형에 내지 재단 사이즈를 넣었는가(표지 한 면이 아니라).
  • coverWidthMm 에 표지 한 면 폭을 넣었는가(펼침면 전체가 아니라).
  • 내지 템플릿 캔버스가 세트 판형과 방향 포함 ±0.01mm 일치하는가. 정합 배너 0 확인.
  • spec.dpi 를 150 으로 두었는가.

책등 가변

  • 기준 책등 폭을 명시 입력했는가(비우면 7.5mm).
  • 저작 후 모든 객체를 한 번씩 이동시켜 meta.regionRef/anchor 를 확정했는가.
  • 페이지 가변 상품에 flat-spread 템플릿을 연결하지 않았는가(조용히 고정된다).
  • 펼침면 전폭 배경을 full 템플릿에 통째로 넣지 않았는가.
  • 책등 텍스트가 최소 페이지 기준 폭에서도 들어가는가. 3mm 미만이면 책등 글자 제외.
  • 앞·뒤표지 요소가 책등 경계에서 safeSizeMm 이상 떨어져 있는가.
  • 지종을 정규 코드로 넣고 formulaVersion==='v2' 인지 확인했는가.
  • 무선/양장 두께를 같은 컬럼에 섞지 않았는가(단위 2배 차이).

구조·등록

  • 책모드 세트에 SPREAD 1개 + PAGE 최소 1개 가 들어 있는가.
  • 펼침면 내지라면 regionScope==='inner' 와 innerSpec 6필드를 저장 후 확인했는가(서버가 안 잡아준다).
  • gutterMm 을 명시 입력했는가(기본값이 경로마다 다르다).
  • pageCountRange 를 [최소, 최대] 물리 페이지로 넣었는가(이산 목록은 강제되지 않고, 펼침면은 ÷2 로 환산된다).
  • 템플릿을 스크립트로 수정할 때 spreadConfig 전체를 덮어써 conversionMode 를 잃지 않았는가.

펼침면 내지 세트

  • 세트 판형에 펼침면 총폭이 아니라 한 면 치수를 넣었는가(A4 펼침면 → 210×297).
  • 연결한 더미 PAGE 템플릿이 세트 판형과 정확히 같은 치수인가(다르면 후보에 안 뜬다).
  • 편집기에서 거터 밴드와 좌/우 면 경계가 보이는가(안 보이면 regionScope 가 안 실린 것).
  • 첫 캔버스 라벨이 '펼침면 1' 인가(‘표지 스프레드’로 뜨면 표지 세트로 열린 것).
  • 표지 세트와 내지 세트를 따로 만들었는가(한 세트에 spread 는 1개만 쓰인다).

canvasData 직접 편집 시

  • 모든 textbox/text/i-text 에 styles:{} 를 넣었는가(없으면 저장이 무한로딩).
  • canvasData 최상위 width/height 를 캔버스 치수로 착각해 넣지 않았는가.
  • 크롭을 clipPath 로 처리하지 않았는가(픽셀에 베이크할 것).
  • 가이드처럼 보이는 점선·치수 라벨이 디자인 객체로 들어있지 않은가(PDF에 그대로 인쇄된다).
  • 고객이 못 건드릴 요소에 위치 고정·삭제 불가·내용편집 잠금을 명시 지정했는가(기본은 잠겨 있지 않다).
