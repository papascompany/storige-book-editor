⚠ 블리드 단위 — 가장 많이 틀리는 곳

cutSizeMm 는 "사방 도련"이 아니라 양변 합이다. 사방 3mm 도련을 원하면 cutSizeMm: 6 을 넣어야 한다. 템플릿셋의 bleedMm(사방)과 단위가 다르다 — 두 값을 같게 넣으면 도련이 절반이 된다.

안전한 운용: 템플릿셋에서 bleedMm > 0 과 함께 "재단선 마커 표기"를 켜라. 게이트가 켜지면 편집기가 bleedMm × 2 로 cutSizeMm 을 덮어써 자동 정합된다. 블리드만 넣고 마커를 안 켜면 고객 화면과 PDF에 블리드가 0으로 나간다.
안전선(safeSizeMm) 주의: 책등 세이프존 가이드는 실제보다 2배 보수적으로 표시된다. 화면 가이드가 빡빡해 보여도 실제 여유는 그보다 크다 — 다만 가이드 안쪽에 배치하는 것을 기준으로 삼는 편이 안전하다.

제작 규칙

  • 기준 책등 폭은 중간값으로. 최소/최대 페이지의 중간 정도. 극단값이면 반대쪽에서 재배치 폭이 커진다.
  • 한 요소는 한 면 안에. 면을 가로지르는 띠·제목 박스는 면별로 잘라서 각각 배치한다.
  • 앞·뒤표지 요소는 책등 경계에서 최소 safeSizeMm 이상 띄운다. 경계에 딱 붙이면 책등이 좁아질 때 이탈 판정이 난다.
  • 뒤표지 객체도 반드시 앵커를 갖게 하라. 앵커 없이 두면 책등이 커질 때 책등 쪽으로 드리프트한다.
  • 책등 글자는 예상 최소 페이지 기준 폭에서도 들어가는 크기로. 무선 3mm 미만 상품에는 책등 글자를 넣지 않는다.
  • conversionMode 는 full 또는 flat-spine 만. flat-spread 는 가변이 차단된다.

  • 템플릿셋 판형 = 내지 재단 W×H(§8).
  • 표지 템플릿 spec 한 면 = 판형 + 8: coverWidthMm = W+8, coverHeightMm = H+8(각 ±0.2mm 이내).

  • 날개 없음(wingEnabled 끔).
  • caseBind 없음 — 템플릿셋 싸바리 값(합지·접힘·wrap)과 표지 템플릿 spec.caseBind 를 모두 비운다. 어느 쪽이든 있으면 모드가 꺼진다. 이전 판의 "3필드 합 28mm" 권장은 철회한 그대로다.

  • 양장 상품은 호스트 파트너가 bindingType=hardcover 를 보내도록 합의한다. 편집 세션 표지 검증 동작은 docs/PLATFORM_INTEGRATION_GUIDE.md 5.3.1 '편집기 산출 표지' 항목(싸바리 모드는 3.1 '양장 싸바리 템플릿셋 표지')을 따른다.

7-3. 쪽수 범위·쪽 추가 단위

Admin 템플릿셋 페이지 그룹의 최소/최대 페이지(pageCountRange)와 페이지 증감 단위(pageStep)가 편집기의 쪽 추가·삭제를 정한다. 호스트 파트너가 /embed 로 같은 종류의 값을 보내면 그 값이 우선한다(§9-1). 아래 제본 한도·호스트 단위 우선은 스프레드 세션(표지펼침면·표지3분할 표지가 있는 세트, 내지펼침면 세트) 기준이며, 단일 모드 예외는 아래 '현재 동작'에 적는다.

  • canAddPage — 고객이 내지를 추가할 수 있는지. 이게 true 여야 책등 가변이 의미를 갖는다.
  • 모든 값은 물리 페이지 기준이다. 내지펼침면은 캔버스 1장 = 2페이지라 [8,40] 이면 펼침면 4~20장이 된다. 캔버스 수로 착각해 넣으면 상·하한이 절반으로 걸린다.
  • pageCountRange 는 [최소, 최대] 2원소 클램프다. [16,24,32,40,48] 처럼 이산 목록을 넣어도 16~48 로만 읽히고 중간값은 강제되지 않는다. "8쪽 단위"가 필요하면 페이지 증감 단위를 쓴다.
  • 페이지 증감 단위 pageStep = N — 내지 물리 쪽수가 N 의 배수여야 한다. 편집기가 그 단위로 추가·삭제하고, 배수가 아니면 편집완료를 막는다. 비우면 제약 없음(1장씩). 배수는 0부터 세므로 최소 페이지도 단위의 배수로 넣는다(단위 8 → 최소 16, 24 …).
  • 펼침면 단위 환산: 캔버스 1장 = 2쪽이므로 단위 8 = 펼침면 4장씩, 단위 4 = 2장씩, 단위 2 = 1장씩(사실상 제약 없음). 내지펼침면 세트의 단위는 짝수로 넣는다 — 홀수 단위 N 은 펼침면에서 실제로 2N 쪽 간격(예: 3 → 6쪽)으로 동작한다.
  • 제본별 최소·최대(호스트가 bindingType 을 보낸 스프레드 세션만): 무선 최소 32p, 중철 최대 64p, 양장·스프링은 제약 없음. 실제 한도 = 범위와 제본 한도 중 좁은 쪽. 단 호스트가 pageCountMin 을 보내면 제본 최소 대신, pageCountMax 를 보내면 제본 최대 대신 그 값을 쓴다(키별 — CONTRACT_FREEZE v1.12). 책등 계산 API 의 제본 경고(§5)는 이와 별개로 비차단이다.
  • 포토북 최소 제작 페이지를 실제로 막으려면 가격 설정의 minPages 만으로는 부족하다 — pageCountRange 최소값에도 같은 수치를 넣어라.
  • 가격 그룹의 증감 단위는 가격 계산용 별도 필드다. 편집기 쪽 추가 단위는 페이지 그룹의 '페이지 증감 단위'다.
  • 상품에 연결하는 세트는 페이지 증감 단위를 반드시 넣는다(2026-10-07). 편집 완료 때 서버가 만드는 내지 검증은 이 단위(호스트가 보낸 단위가 있으면 그 값)로 쪽수를 판정한다 — 내지펼침면 세트는 펼침 단위로 환산(단위 4 → 펼침 2의 배수). 단위를 비워 둔 낱장 내지 세트는 서버가 제본 고정 규칙(무선·중철 4의 배수)으로 판정하므로, 2쪽 단위 상품을 단위 없이 연결하면 18·22쪽 같은 정상 주문이 쪽수 오류로 표시된다. 단위는 호스트 상품등록 값과 같게(아래 일치 원칙).
일치 원칙 — 템플릿셋 쪽수 설정은 호스트 상품등록 값과 같게. 호스트 파트너 관리자의 상품등록 값(최소·최대 쪽수, 쪽 추가 단위)과 템플릿셋의 최소/최대 페이지·페이지 증감 단위를 같은 값으로 설정한다. 두 값이 같을 때 상품 화면과 편집기의 쪽 추가 동작이 일치한다.
현재 동작: 값이 다르면 호스트가 보낸 값이 적용되고 템플릿셋 값은 호스트가 보내지 않은 키에만 쓰인다. 호스트 단위가 템플릿셋 단위와 다르면 '첨부 PDF 빈 페이지 채움'이 꺼진다. 호스트 최소 쪽수가 호스트 단위의 배수가 아니면 호스트 단위는 무시되고 템플릿셋 단위가 적용된다. 단일 모드 세트(스프레드 표지·내지펼침면이 없는 세트 — 예: 내지낱장 전용 책모드 세트, 비책모드 세트)는 제본별 최소·최대가 적용되지 않고, 표지 등 내지가 아닌 캔버스가 있으면 호스트 단위(1 제외)는 무시되고 템플릿셋 단위가 적용된다. 불일치 시 처리 방식은 별도 결정 사항이므로 불일치 상태로 운영하지 않는다. apps/editor/src/utils/hostPageLimits.ts resolveStorePageLimits() · resolveHostPageLimits() · utils/pageStep.ts · hooks/useEditorContents.ts(단일 모드 ignoreHostStep · 스프레드 로더 bindingType)

9-2. 표지 책등 방식 결정 규약

상품별 표지 모드(표지펼침면 = 책등 고정 / 표지3분할 = 책등 가변)는 호스트 파트너가 정한다. Storige 는 그 규약대로 템플릿을 제작·등록하고, 임의로 바꾸지 않는다.
1
호스트 파트너가 상품의 표지 모드를 정해 알린다
판형·제본·쪽수 범위·쪽 추가 단위와 함께 받는다. 책등 가변이면 spineWidthMm 또는 paperType+bindingType 을 보낼지도 함께 정한다. 책등 고정 양장이면 책등을 정할 기준 쪽수도 함께 정한다(§4-1).
2
Storige 는 그 모드로 표지 템플릿을 만든다
표지펼침면 → conversionMode: 'flat-spread'(§4). 표지3분할 → full 또는 flat-spine(래스터 3분할 PNG)(§3·§4). 양장이면 표지 치수는 §4-1 규격.
3
세트에는 그 모드의 표지만 넣는다
한 세트에 표지펼침면과 표지3분할을 섞으면 서버가 400 으로 막는다. 쪽수 설정은 §7-3 일치 원칙대로.
4
모드 변경은 호스트 결정으로만
모드가 바뀌면 호스트가 보내야 할 값(책등·지종)과 책등 처리가 달라진다 — 고정→가변: 책등·지종을 보내지 않는 상품은 기본 용지(mojo_80g)와 호스트 제본 코드(없으면 perfect)로 서버가 계산한 책등이 들어간다(mojo_80g 는 기본 등록값에 v2 두께가 없어 v1 레거시 식으로 계산된다 — §5). 가변→고정: 호스트가 보낸 책등·지종은 무시되고 템플릿에 등록된 책등이 쓰인다. 스크립트로 spreadConfig 를 덮어써 conversionMode 를 잃는 것(미지정 = 표지3분할)도 모드 변경이다(§10 구조·등록).
모드 변경은 호스트 파트너가 결정한 경우에만 하고, Storige 는 템플릿 교체 시점을 호스트에 미리 알린 뒤 교체한다.
모드는 표지 템플릿의 conversionMode 로만 판정된다(미지정 = full = 표지3분할). Admin 템플릿 목록의 표지펼침면 / 표지3분할 / 내지펼침면 태그로 등록 결과를 확인하라. packages/types/src/print-template.ts classifyPrintTemplate()

치수·단위

  • cutSizeMm 에 사방 도련 × 2 를 넣었는가(3mm → 6). 세트 bleedMm 과 단위가 다르다.
  • 블리드를 쓴다면 재단선 마커 표기도 켰는가. 안 켜면 PDF 블리드가 0이다.
  • 세트 판형에 내지 재단 사이즈를 넣었는가(표지 한 면이 아니라).
  • coverWidthMm 에 표지 한 면 폭을 넣었는가(펼침면 전체가 아니라).
  • 내지 템플릿 캔버스가 세트 판형과 방향 포함 ±0.01mm 일치하는가. 정합 배너 0 확인.
  • spec.dpi 를 150 으로 두었는가.

책등 가변

  • 기준 책등 폭을 명시 입력했는가(비우면 7.5mm).
  • 저작 후 모든 객체를 한 번씩 이동시켜 meta.regionRef/anchor 를 확정했는가.
  • 페이지 가변 상품에 flat-spread 템플릿을 연결했다면 그것이 호스트가 정한 '책등 고정' 모드인가(쪽수와 무관하게 책등이 조용히 고정된다 — §9-2).
  • 펼침면 전폭 배경을 full 템플릿에 통째로 넣지 않았는가.
  • 책등 텍스트가 최소 페이지 기준 폭에서도 들어가는가. 3mm 미만이면 책등 글자 제외.
  • 앞·뒤표지 요소가 책등 경계에서 safeSizeMm 이상 떨어져 있는가.
  • 지종을 정규 코드로 넣고 formulaVersion==='v2' 인지 확인했는가.
  • 무선/양장 두께를 같은 컬럼에 섞지 않았는가(단위 2배 차이).

구조·등록

  • 책모드 세트에 표지 구조 1종(표지펼침면·표지3분할 혼합 금지)과 내지 구조 1종(낱장·펼침면 혼합 금지)만 들어 있는가. 표지·내지 중 최소 1개.
  • 펼침면 내지라면 regionScope==='inner' 와 innerSpec 6필드를 저장 후 확인했는가(서버가 안 잡아준다).
  • gutterMm 을 명시 입력했는가(기본값이 경로마다 다르다).
  • pageCountRange 를 [최소, 최대] 물리 페이지로 넣었는가(이산 목록은 강제되지 않고, 펼침면은 ÷2 로 환산된다).
  • 템플릿을 스크립트로 수정할 때 spreadConfig 전체를 덮어써 conversionMode 를 잃지 않았는가.

펼침면 내지 세트

  • 세트 판형에 펼침면 총폭이 아니라 한 면 치수를 넣었는가(A4 펼침면 → 210×297).
  • 편집기에서 거터 밴드와 좌/우 면 경계가 보이는가(안 보이면 regionScope 가 안 실린 것).
  • 내지 전용 세트라면 첫 캔버스 라벨이 '펼침면 1' 인가(‘표지 스프레드’로 뜨면 표지 세트로 열린 것).
  • 내지펼침면 템플릿을 표지 모드로 오판하지 않았는가. 표지 모드는 표지 템플릿의 conversionMode 로만 정해진다. 내지펼침면은 regionScope:'inner' 로만 판정되며, 이 값이 빠진 펼침면 템플릿은 표지로 분류된다 — conversionMode 가 flat-spread 이면 표지펼침면, 그 밖이면 표지3분할(print-template.ts classifyPrintTemplate). 목록 태그가 내지펼침면 인지 확인.
  • 쪽 추가 단위를 펼침면 장 수가 아니라 물리 쪽수로 넣었는가(8쪽 단위 상품 = 8, 4 를 넣으면 4쪽 단위로 열린다).

호스트 연동·양장

  • 표지 템플릿의 모드가 호스트 파트너가 정한 상품 모드와 같은가(§9-2). 바꿔야 하면 호스트 결정에 따라, 교체 시점을 호스트에 알린 뒤 교체.
  • 템플릿셋 최소/최대 페이지·페이지 증감 단위가 호스트 상품등록 값과 같은가(§7-3). 특히 내지펼침면 세트의 단위가 호스트 pageStep 과 같은 물리 쪽수인가.
  • 책등 가변 템플릿 상품이면 호스트가 지종(paperType)과 제본(bindingType)을 보내는가. 안 보내면 기본 용지(mojo_80g)·무선 공식으로 계산되고, spineWidthMm 만 보내면 쪽을 늘려도 책등이 고정된다.
  • 표지펼침면 상품에 호스트 책등·지종 값이 와도 반영되지 않는다는 점을 호스트 파트너와 공유했는가.
  • 양장 표지 원고 치수가 싸바리 전개 규격((W+8)×2+책등+40 × (H+8)+40)인가(§4-1). 싸바리 값(caseBind)을 템플릿셋에도 표지 템플릿 spec 에도 임의로 넣지 않았는가.
  • 양장 표지 세트가 싸바리 모드 규약(커버 종류 hardcover_wrap · 한 면 = 판형+8 · 날개·caseBind·외곽선 없음 · cutSizeMm 저장값 유지)을 지켰는가(§4-1). 편집기에서 사방 20mm 여분 가이드가 보이는지 확인.
  • 책등 고정(표지펼침면) 양장이면 책등을 호스트와 정한 값으로 넣고, 쪽수 범위 양 끝 차이가 허용오차 안인지 확인했는가(§4-1).
