재단선 포함 PDF · TrimBox 처리

인쇄용 PDF 는 종이 전체 크기(MediaBox) 안에 실제로 잘릴 크기(TrimBox)와 여분 인쇄 영역(BleedBox)을 따로 적습니다. 지금 worker 는 MediaBox 만 보고 판형을 판정해서, 재단선이 포함된 정상 파일을 크기 불일치로 거부합니다.

실측 파일 B · 박스 구조 (실제 비율, 1mm = 1단위)

MediaBox · 종이 전체 BleedBox · 여분 인쇄 TrimBox · 재단 크기 재단선(crop marks)

현재 판정과 바뀌는 판정

현재 · MediaBox 236×323 을 기대 판형 210×297(또는 bleed 포함 212×299)과 비교 → SIZE_MISMATCH 로 거부. 파트너에는 session.failed 계열로 전달됩니다.
변경 후 · TrimBox 가 파일에 명시돼 있고 MediaBox 보다 작으면 TrimBox 210×297 을 기대 판형과 비교 → 통과. 합성할 때는 재단선 영역을 잘라 TrimBox + 주문 bleed 크기로 맞춥니다.

원본 PDF 는 재단선 영역을 포함한 채 보존됩니다. 원본을 그대로 인쇄 입력으로 쓰는 흐름(첨부 원본 직접 사용)은 인쇄소 RIP 의 TrimBox 처리에 맡기며, 원본 정규화 사본 등록은 후속 과제입니다.

pdf-lib 의 getTrimBox() 는 TrimBox 가 없으면 MediaBox 를 대신 돌려줍니다. 그래서 판별은 페이지 사전에 /TrimBox 가 실제로 있는지로 합니다. MediaBox 만 있는 PDF(100p 등)는 새 경로에 들어가지 않습니다.

일치 → 판형 통과. 비차단 경고 TRIMBOX_SIZE_BASIS 를 추가하고 metadata.trimBox 를 채웁니다(모두 추가 필드).
불일치 → 기존 SIZE_MISMATCH 그대로(메시지·details.actual 불변). details.trimBox 만 추가.
4
bleed 판정 — 모든 페이지·모든 변에서 BleedBox − TrimBox 의 최소값을 도련으로 봅니다. BleedBox 가 없으면 0 입니다. 재단선 영역(MediaBox 여백)은 그림이 없는 영역이라 도련으로 치지 않습니다. 주문 bleed 보다 작으면 기존 BLEED_MISSING 경고가 그대로 나갑니다(파일 A).
5
합성·변환 크롭 정규화 — 임시 사본만 자르고 원본은 건드리지 않습니다.
  • 변환(도련 보정·내지 조판·쪽수 채움 — 작업 크기를 앎): 작업 크기에 정확히 맞춥니다. 파일 B·사방 4mm 파일 모두 212×299mm, 축소 인쇄(innerfit) 없음.
  • 합성(merge·spread·compose — 주문 도련을 모름): BleedBox 가 명시돼 있고 그 밖에 사방 5mm 이상 균등한 재단선 영역이 있을 때만 TrimBox + min(선언 도련, 3mm) 로 자릅니다. 파일 A → 210×297, 파일 B → 216×303.
  • BleedBox 가 없으면 합성에서는 자르지 않고 원본 박스를 유지합니다. 어느 경우든 TrimBox 는 페이지 중앙(±0.5pt)에 남아 인쇄소 재단 기준이 됩니다(Ghostscript 재증류 뒤에도 실측 확인).
  • 쪽수 채움 백지는 정규화된 페이지와 같은 좌표계로 만듭니다.
한계: 합성 산출물은 주문 도련 대신 선언 도련으로 나갈 수 있습니다. 후속으로 API 가 합성 잡에 주문 도련·재단 크기를 넘기면 해소됩니다.
6
안전장치 — 긴급 차단 플래그 WORKER_TRIMBOX_SIZE_CHECK: 코드 기본값 켜짐, false/0/off/no 로만 꺼짐. compose 에 ${WORKER_TRIMBOX_SIZE_CHECK:-true} 로 매핑해 .env 한 줄로 끌 수 있게 하고, 기동 로그 스냅샷에 실효값이 찍힙니다. 꺼지면 판정·정규화 모두 종전 동작입니다.
