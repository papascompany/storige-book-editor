## 2. `editor.saved` 가 `ok:false` 일 수 있습니다 — 조건부 조치

편집기가 **초기화/재초기화 중**(진입 로딩, 고객이 "변경 이력 → 여기로 복원" 실행 직후 캔버스 재구성 구간)에 `saveNow` 역명령을 받으면 저장을 **거부**하고 아래로 응답합니다:

```json
{ "requestId": "...", "ok": false, "error": "EDITOR_BUSY" }
```

- 이유: 이 창에 저장하면 미완성 캔버스가 서버의 정상 작업물을 덮어쓸 수 있어 서버 보호를 위해 거부합니다. **직전 자동저장본은 서버에 안전하게 남아 있습니다.**
- 조치: `editor.saved` 수신부에서 **`ok` 를 분기**하세요. `EDITOR_BUSY` 면 잠시 후(1~3초) 재시도하거나, 이탈 플로우라면 그대로 진행해도 됩니다.
- `ok` 를 확인하지 않던 수신기는 동작 변화가 없습니다. **`saveNow` 역명령 자체를 쓰지 않으면 이 항목은 해당 없음**입니다.

## 3. 세션 API 테넌트 격리 — 확인 권장

`memberSeqno` 는 사이트별 독립 번호공간이므로, 이제 회원 세션 라우트 전부가 shop-session JWT 의 `siteId` 와 세션의 `siteId` 를 대조합니다.

- `GET/PATCH /api/edit-sessions/:id` · `:id/complete` · `DELETE :id` · `:id/versions*`: 타 사이트 세션이면 **`404 SESSION_NOT_FOUND`**
- `GET /api/edit-sessions?orderSeqno=` · `GET /api/edit-sessions/my`(편집보관함): 타 사이트 세션은 **조용히 목록에서 제외**
- 귀사처럼 **하나의 Site 로 발급·진입·재편집을 일관**하면 영향이 없습니다.
- ⚠️ 한 가지 유의: 과거 **다른 연동(bookmoa PHP 쇼핑몰) Site 로 생성된 세션**은 mobile 쪽 JWT 로 더 이상 조회/재편집되지 않습니다. 현재 PHP 연동은 휴면 상태라 실영향은 없는 것으로 파악하고 있으나, 혹시 PHP 시절 `sessionId` 를 재사용하는 코드가 남아 있다면 정리를 권장합니다.
- 진단: 재편집이 예기치 않게 `404` 가 나거나 보관함이 비면, **진입 JWT 를 발급한 API 키의 Site 와 세션 생성 시점 Site 가 같은지** 먼저 확인해 주세요(불일치 시 저희 서버 로그에 `[tenant-scope]` 경고가 남아 함께 추적 가능합니다).

## 4. (참고) 고객 셀프 복원 — 편집기 헤더 "변경 이력"

고객 작업물이 저장 사고(페이지 절단·오저장)로 덮어써져도, 서버가 덮어쓰기 직전 상태를 자동 보관하고 고객이 편집기 헤더 🕘 **변경 이력 → 여기로 복원** 으로 직접 되돌릴 수 있습니다(자동저장 1분 간격 + 페이지 감소 직전 즉시, 최근 10개 보관). "작업이 날아갔다" 문의가 오면 이 경로를 먼저 안내해 주세요. 파트너측 연동 변경은 없습니다.

## 5. 문의

이상 동작(예기치 않은 404·빈 보관함·`EDITOR_BUSY` 반복)이 관찰되면 발생 시각·`sessionId`·요청 경로와 함께 기존 채널로 연락 주세요.
