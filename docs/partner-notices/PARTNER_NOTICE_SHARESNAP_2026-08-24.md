## 2. `editor.saved` 가 `ok:false` 일 수 있습니다 — 조건부 조치

편집기가 **초기화/재초기화 중**(진입 로딩, 고객이 "변경 이력 → 여기로 복원" 실행 직후 캔버스 재구성 구간)에 `saveNow` 역명령을 받으면 저장을 거부하고 다음과 같이 응답합니다:

```json
{ "requestId": "...", "ok": false, "error": "EDITOR_BUSY" }
```

- 이 창에 저장하면 미완성 캔버스가 서버 작업물을 덮어쓸 수 있어 서버 보호를 위해 거부합니다. 직전 자동저장본은 서버에 안전합니다.
- 조치: `editor.saved` 수신부에서 **`ok` 를 분기**하고, `EDITOR_BUSY` 면 잠시 후(1~3초) 재시도 또는 이탈 플로우 그대로 진행. `saveNow` 를 쓰지 않으면 해당 없음.
- 아직 연동 구현 단계이므로, 수신 핸들러 초기 구현에 이 분기를 포함해 두시길 권장합니다(가이드 §3.6 체크리스트에도 반영돼 있습니다).

## 3. 세션 API 테넌트 격리 — 무영향 확인

회원 세션 라우트 전부가 shop-session JWT 의 `siteId` 와 세션 `siteId` 를 대조합니다(타 사이트: `:id` 계열 `404 SESSION_NOT_FOUND`, 목록/보관함은 조용한 제외). 귀사는 단일 Site 로 발급·진입·재편집이 일관되므로 영향이 없습니다. 재편집 404·빈 보관함이 보이면 진입 JWT 를 발급한 키의 Site 와 세션 생성 Site 일치 여부를 먼저 확인해 주세요.

참고로 귀사에서 쓰는 사진 주입(`metadata.externalPhotos`)·`compose-mixed` 경로는 이번 변경과 무관하게 그대로입니다.

## 4. (참고) 고객 셀프 복원

서버가 canvasData 덮어쓰기 직전 상태를 자동 보관(자동저장 1분 간격·페이지 감소 직전 즉시·최근 10개)하고, 고객이 편집기 헤더 🕘 **변경 이력 → 여기로 복원** 으로 직접 되돌릴 수 있습니다. 파트너측 변경 없음.
