## 1. 운영 원칙 (Storige 오너 결정, 즉시 적용)

- **대상**: 파트너 주문에 연결된 세션(`orderSeqno` 있음). 주문 전 세션은 제한 없이 작업합니다.
- **사전 통지**: Storige 관리자가 이 세션을 수정·완료·삭제하기 **전에** 해당 파트너 창구에 알립니다(주문번호, 세션 id, 할 작업).
- **사후 통지**: 작업 **뒤에** 다음을 전달합니다.
  - 세션 id
  - 새 fileId(표지·내지·첨부 내지)
  - 시각(UTC)
  - 삭제한 경우에는 세션 id와 삭제 시각
- **파트너 반영**: 파트너가 통지받은 값으로 주문(`items[].storige` 등)을 수동 반영합니다. 반영 방법은 각 사 구조를 따릅니다.
- **합성/재합성**: 관리자 합성은 세션의 fileId를 바꾸지 않습니다. 파트너 알림은 기본 꺼짐이라 파트너 콜백·웹훅과 파트너 조회의 최신 합성 결과에 나타나지 않습니다. 알림을 켜면 종전 규칙대로 전달됩니다.

## 2. 관리 화면 안전장치 (배포 완료)

- 배포: admin 커밋 `4caa7cc`, Vercel `hcgs4hn2c` Ready(2026-09-30 02:34Z). 서버·편집기는 배포하지 않았습니다(변경 없음).
- 편집 세션 목록과 삭제 리스트에서, 주문번호가 있는 세션에 `주문 연결` 태그가 붙습니다.
- 편집기 열기·완료 처리·삭제·합성/재합성을 누르면 확인 창이 뜹니다. 창에는 파트너 주문에 미치는 영향이 표시되고, '사전 통지했습니다'를 체크해야 진행됩니다.
- `통지 정보 복사` 버튼은 복사 직전에 세션을 다시 읽어 사후 통지용 텍스트를 만듭니다. 텍스트에는 사이트, 주문번호, 세션 id, 상태, 편집완료·수정·삭제 시각(UTC), 표지·내지·첨부 내지 fileId, 작성 시각(UTC)이 들어갑니다.
- 관리자 편집 뒤에 완료 기록이 없으면 텍스트에 "파일 ID는 편집 전 PDF" 주의 문구가 붙습니다. 관리 화면의 `완료 처리`는 PDF를 새로 만들지 않으므로, Storige는 관리자 편집분을 편집기의 편집완료로만 반영하도록 운영합니다(확인 창에서도 안내).

## 3. 파트너 영향

- 파트너 API, 웹훅, 응답 형식은 **바뀌지 않습니다**. 코드 변경은 필요 없습니다.
- 알아 두실 동작:
  - 관리자가 편집기에서 **저장**만 하면 세션 내용만 바뀌고 fileId는 그대로입니다. **편집완료**를 해야 새 fileId가 생깁니다.
  - 관리자가 **삭제**하면 저장된 sessionId로 여는 재편집과 세션 기반 합성은 404 `SESSION_NOT_FOUND`가 됩니다. sessionId 없이 `orderSeqno`로 편집기를 열면 새 빈 세션이 만들어질 수 있습니다.

## 4. 한계

- Storige는 `orderSeqno`로만 주문 연결을 판단합니다. 주문번호 없이(0으로) 만든 세션을 주문에 쓰는 경우, 예를 들어 게스트 세션을 회원 세션으로 전환한 뒤 주문한 경우에는 `주문 연결`로 표시되지 않습니다.
- 양사 주문 흐름에 이런 경우가 있으면 알려 주세요.
