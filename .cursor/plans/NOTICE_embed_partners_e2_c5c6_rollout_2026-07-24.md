## 2. 계약 보장 (변경 없음)
- **postMessage 엔벨로프 v1 시맨틱 불변** — 이벤트/명령 추가·변경 0건. 동결 라우트 무접촉.
- **canvasData 직렬화 하위호환** — 신규 직렬화 속성 0건. C5 사본은 기존 복제(Ctrl+D) 파이프라인을 그대로 재사용하므로 저장·재편집 왕복 무손실.
- **관리자 보호객체 규약 불변** — 위치고정/삭제잠금 등 보호객체는 C5 복제 대상에서 제외(고객이 보호를 우회 복제 불가).
- 신규 기능은 전부 **additive + 기능 플래그**. 문제 시 Storige 측에서 플래그 off 로 즉시 롤백(단, 플래그는 editor 배포 단위 전역 — 사이트별 개별 off 미지원).

## 3. 요청 사항 (회귀 확인)

### 3-1. 공통 (bookmoa-mobile · ShareSnap)
1. 기존 골든 시나리오 1회: 상품/세션 진입 → iframe 로드 → 편집(객체 추가·이동) → 저장 → 완료 콜백 정상 수신.
2. C6 배포 후: 모바일 실기에서 객체 롱프레스 → 메뉴 표시 → 항목 실행 정상, 롱프레스 중 **스크롤/드래그와 오작동 없음**.
3. C6 모바일 롱프레스 동작 변경을 **QA·CS에 사전 공유**(사용자 문의 대비).
4. 참고(의도된 동작): **빈 캔버스 영역**을 롱프레스하면 '붙여넣기'만 있는 메뉴가 표시될 수 있습니다(데스크탑 우클릭과 동일). 오류 아님.

### 3-2. ⚠️ ShareSnap 전용 (핀치줌 D2 흐름 인접)
- ShareSnap의 **핀치줌(두 손가락)** 사용 흐름과 C6 롱프레스가 인접합니다. Storige는 "**두 번째 손가락 도착 즉시 롱프레스 취소 → 핀치 정상**"으로 설계했으나, **실기 교차 확인**을 요청드립니다:
  - 사진 배치 중 롱프레스 → 메뉴, 그 상태에서 핀치줌 전환이 매끄러운지.
  - 저사양 기기에서 롱프레스↔핀치 전환 시 프레임 드랍/오작동 없는지.

### 3-3. 이상 발견 시
증상 + 세션 ID + 기기/뷰포트(예: iPhone Safari / Android Chrome, 375폭)를 Storige로 회신 → 플래그 off 롤백 판단.
