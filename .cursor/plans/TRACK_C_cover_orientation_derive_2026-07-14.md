# [별도 트랙 C] 표지(spread) 방향 파생 자동화 — 설계 착수 노트

> 상태: **미착수(설계 노트)**. 2026-07-14 방향 쌍 관리(derive-orientation) 배포 시 표지는 의도적으로
> 제외했고(내지 page류만 자동 이월), 표지 세로↔가로 변환은 이 트랙에서 다룬다.
> 관련: RESUME_PROMPT_2026-07-14.md §2-3, docs/HARDCOVER_COVER_VALIDATION_NOTES.md

## 1. 왜 별도 트랙인가 (내지와 다른 이유)

- 내지(page)는 단일 면이라 W↔H 스왑 + 축별 비율 재배치로 충분(이미 구현·배포).
- 표지(spread)는 **[뒤표지 | 책등 | 앞표지] 3영역 펼침면**:
  - 각 면이 세로↔가로로 **개별 회전**해야 함(앞표지 210×297 ↔ 297×210).
  - **책등 폭이 페이지수·용지 종속 가변** → 전체 폭이 방향과 무관하게 재계산 필요.
  - 전체 치수가 W↔H 스왑이 아님(세로 429.2×301 → 가로 603.2×214, 스왑이면 301×429).
- 즉 "전체 비율 스왑"으로는 앞/책등/뒤 경계가 깨진다. (2026-07-14 B 임시조치는 책등이
  1.2mm로 매우 얇아 전체 비율 근사가 우연히 통했을 뿐 — 두꺼운 책등에선 틀어짐.)

## 3. 정식 설계 방향

1. **spread 기하 파서**: templateSet/템플릿의 spread config(SpreadPlugin spec) 조사 —
   앞/책등/뒤 영역 경계, 도련, 책등 폭 산출 규칙(페이지수·용지 두께)을 구조로 확보.
   (조사 시작점: packages/canvas-core SpreadPlugin, apps/api template-set spreadConfig,
   photobook-template 스킬 문서의 펼침면 규약.)
2. **면 단위 변환**: 각 객체를 소속 면(앞/책등/뒤)으로 분류 → 면 로컬 좌표로 이동 →
   그 면의 세로↔가로 회전 변환(W↔H 스왑 + 로컬 비율) → 새 방향 면 절대좌표로 복원.
   책등 영역 객체(제목 세로쓰기 등)는 책등 폭 재계산 반영.
3. **derive-orientation 확장**: 현재 page류만 이월하는 로직에 spread 분기 추가(옵션 플래그
   `includeCover`). 기본은 현행 유지(표지 제외), 명시 시에만 표지 변환 이월.
4. **admin UX**: 파생 confirm 모달에 '표지도 변환 이월(실험)' 체크 + 초안 경고 강화.
5. **검증**: 실 표지 canvasData 픽스처(MA-348 spread 8객체 등)로 왕복 오차·면 경계 보존 spec.
   골든 렌더 파리티(표지 PDF)까지 권장.
