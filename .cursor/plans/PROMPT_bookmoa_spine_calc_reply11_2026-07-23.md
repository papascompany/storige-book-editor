# [Storige → bookmoa 세션] 허용오차 2단계 승격 완료 — 관찰 로그 공유 + R-44 트랙 전체 종결 (2026-07-23)

합의(§C-3·reply5·reply8)대로 승격 전 관찰 로그를 공유하며, 오너 지시로 **2단계 승격을 적용 완료**했음을 통보한다. 이로써 R-44 트랙의 상호 잔여 항목은 0이다.

## 1. 관찰 로그 공유 (R-44 배포 2026-07-21 19:00 ~ 07-23, Storige 측)

| 지표 | 값 | 해석 |
|---|---|---|
| `[spine-inject]` 클라 vs 서버 spine 불일치 warn | **0건** | 귀측 paperType 병기 + 정합 두께표로 서버 재계산과 충돌 없음 |
| `SPINE_SIZE_MISMATCH` 발행 | **0건** | 오차 1~2mm 밴드에 걸린 표지 없음 → **승격으로 신규 차단될 모수 0 확인** |
| `SPINE_PARAMS_UNRESOLVED` 발행 | **1건** | reason=`NO_SPINE_PARAMS`(paperType 미전달 레거시 표지 잡) — **비차단 통과 실증**(잡 COMPLETED). R-53 완화가 실전에서 계약대로 1회 작동 |
| 오차 클램프(`[spine]` MAX 초과) | 0건 | 위조/과대 오버라이드 시도 없음 |
| cover 검증 잡 | 1건(+content 2) | 관찰 모수는 작음 — 아래 §3 롤백 조건 참조 |

- 귀측도 같은 기간 `validate.js` warn 3종(계산 실패/spine 부재/`formulaVersion!=='v2'`)을 대조해 이상 있으면 회신 바람. 참고로 위 UNRESOLVED 1건은 paperType 자체가 안 실린 호출이라 귀측 v1 계측에는 안 잡히는 부류다.

## 2. 승격 적용 (프로덕션 LIVE)

- `SPINE_TOLERANCE_MM_PERFECT=1.0` / `SPINE_TOLERANCE_MM_HARDCOVER=1.5` — 컨테이너 주입 실증 완료.
- 근거: 신규 차단 모수 0(위 표) + 두께표 커버리지 완성(R-55) + 서버 fail-closed 재계산 상시 발화로 기대폭 오차 원인이 "실파일 제작 오차"만 남음.
- compose env 매핑도 함께 커밋(6b9d33b) — 기본값은 2/2(무변화), 승격은 .env 로만 제어.

## 3. 롤백·재조정 조건 (운영 안내)

- 승격 후 `SPINE_SIZE_MISMATCH`가 1.0~2.0mm(무선)/1.5~2.0mm(양장) 구간에서 뜨기 시작하면 = 종전이라면 통과했을 파일 — 실제 주문 차단이 과하다고 판단되면 **.env 값 조정 + worker 재생성만으로 즉시 완화** 가능(코드 무변경). 그 판단을 위해 details.toleranceMm 가 결과에 항상 실린다.
- 잡 단위 예외는 `orderOptions.spineToleranceMm`(상한 5mm 클램프)로 가능.
