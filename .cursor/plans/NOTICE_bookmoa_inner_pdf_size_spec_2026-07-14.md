# [Storige → bookmoa] 내지 PDF 판형(size) 전달 규격 확정 안내

> 발신: Storige 개발팀 · 2026-07-14
> **파괴적 변경 없음** — 검증 임계값·에러/경고 분류·오차허용 체계는 전부 종전과 동일합니다.
> 이번 변경은 ① 판형 규격표 확정 ② 가로형 상품의 방향(W↔H) 정합 안전망 ③ 방향 안내 경고 추가입니다.
> 기술 정본: 공유 레포 `docs/PDF_VALIDATION_GUIDE.md` § 내지 판형 규격표 (2026-07-14)

## 1. 판형 규격표 — 재단 / 작업(= 재단 + 사방 3mm)

`orderOptions.size` 로 전달하는 값은 **재단 사이즈(mm)** 입니다. 아래는 세로형 기준 표기입니다.

| 판형 | 재단 (W×H mm) | 작업 (+사방 3mm) |
|---|---|---|
| A4 | 210×297 | 216×303 |
| A5 | 148×210 | 154×216 |
| B5 | 182×257 | 188×263 |
| 46배판 | 188×257 | 194×263 |
| 16절 | 190×260 | 196×266 |
| B6 | 128×182 | 134×188 |
| 정사각 | 210×210 | 216×216 |
| 비규격 | **고객 입력값 그대로** | 입력값 + 사방 3mm |

- 고객 업로드 PDF 는 **재단 또는 작업 어느 쪽 사이즈든 정상 처리**됩니다.
  재단 사이즈 업로드 시에는 도련이 자동 삽입(콘텐츠 무확대, 중앙 배치)되어 작업 사이즈로 변환·저장됩니다.
- **가로형 상품**: 동일 판형의 W↔H 스왑(예: 가로 A4 재단 = 297×210). 방향만 다르고 기준은 동일합니다.
- **비규격**: 고객이 입력한 재단값을 가공 없이 그대로 전달해 주세요(+ `bleed: 3`).
  Storige 는 전달값을 그대로 검증 기준으로 사용합니다.

## 2. size 전달 원칙 (요청 사항)

- **상품 방향대로 오리엔트된 재단값을 보내 주세요.** 가로형 상품이면 `{ "width": 297, "height": 210 }`.
  (기존 연동에서 가로형 상품에도 세로 값 210×297 이 전달되는 사례가 확인되었습니다.)
- 전달값이 해당 상품 판형의 **정확한 W↔H 스왑**인 경우 Storige 서버가 자동 정규화하는
  안전망이 있으나, 이는 임시 안전망이며 **원칙은 오리엔트 전달**입니다.
  정규화가 발생하면 Storige 서버 로그에 계측되므로, 교정 완료 여부를 로그 소멸로 상호 확인할 수 있습니다.
- 판형별 전달값을 위 규격표와 대조해 주세요. 특히 **46배판(188×257)과 16절(190×260)** 혼동에 주의 바랍니다.

## 3. Storige 서버 동작 변경분 (2026-07-14 배포됨)

1. **정확 스왑 정규화(안전망)**: 전달 size 가 상품 판형과 정확히 W↔H 스왑 관계(정사각 제외)일 때만
   상품 방향으로 정규화합니다. 스왑이 아닌 불일치는 **전달값 원본 그대로** 검증합니다(종전 계약 불변).
2. **방향 안내 경고**: 업로드 PDF 페이지 방향이 상품 방향과 다르면 `ORIENTATION_MISMATCH`
   **경고(비차단)** 가 검증 결과에 포함됩니다 — 주문 차단이 아니며 isValid 판정에 영향 없습니다.
   고객 노출 문구 예: "가로형 상품인데 세로 방향 페이지가 포함되어 있습니다. 의도한 방향인지 확인해 주세요."
3. **판형 검증 자체는 무변경**: 가로 상품에 세로 PDF 를 올리면 종전대로 SIZE_MISMATCH 로 차단됩니다
   (+ 위 방향 안내가 함께 제공됩니다).

## 4. 미전달 시 폴백 (기존 동작 명기)

- `size` 미전달 시: 상품에 연결된 templateSet 판형으로 폴백 → 그것도 없으면 최후 A4(210×297).
- 직접 검증 API(`POST /api/worker-jobs/validate/external`)는 종전 계약 그대로 — 전달한 값만 사용합니다.

## 5. bookmoa 필요 작업 요약

| 구분 | 내용 |
|---|---|
| 필수 | 없음 (비파괴 — 기존 전달값도 종전과 동일하게 동작) |
| 권장 | 가로형 상품 size 오리엔트 전달 교정 / 판형별 전달값 규격표 대조 |
| 선택 | ORIENTATION_MISMATCH 경고의 고객 문구 노출 |

## [부록] 함께 안내드리는 기존 변경 2건 (2026-07-13 배포분)

### A. `editor.complete` / `editor.pricingChange` 의 `pageCount` 값 정정 (21→20)

표지+내지 단일 세션(book 상품)에서 `pageCount` 가 표지 스프레드를 +1 로 산입해
**내지 20p 주문이 21 로 전달되던 오류를 정정**했습니다. 이제 `pageCount` = **내지 물리 페이지 수**
(주문 옵션의 페이지 수와 동일 기준)입니다. payload 구조는 불변, 값만 정정입니다.
bookmoa 장바구니/가격 로직이 종전 21 기준으로 보정하고 있었다면 교차 확인 바랍니다.

### B. 표지/내지 PDF 분리 산출 — `outputFormat` 지정 안내

주문 시점 합성을 `POST /api/worker-jobs/synthesize/external` 로 호출하는 경우 기본값이
`merged`(합본 1파일)입니다. **표지 PDF / 내지 PDF 분리 산출이 필요하면 `outputFormat: "separate"`**
를 명시해 주세요. (`compose-mixed` 경로는 spread book 에서 자동 separate — 해당 없음)
