## 1. §5 서버 시드 — 완료·프로덕션 LIVE (커밋 21248c1)

- 회신받은 caliper 10항목 전량을 `paper_types`에 편입(양장=caliper mm/장, 무선=caliper÷2 mm/페이지, ± 공차는 중앙값 — 귀측 모달과 동일값). 시드 로그 실증: created=10, backfilled=10.
- **정밀도 이슈 선제 해소**: 아르떼105(0.0775)·뉴플러스80(0.0405)은 소수 4자리 — DB 컬럼을 DECIMAL(7,4)로 확장(마이그레이션 20260722)해 반올림 없이 저장. scale 3이었다면 200p 기준 모달과 0.1mm 어긋났을 것.
- **라이브 실증(모달 파리티)**: 무선 아르떼(UW)105 200p → **15.5mm** · 무선 이라이트80 200p → **13mm** · 양장 이라이트80 200p → **17mm**(귀측 라이브값과 일치) · 양장 모조220 200p → 29mm · 무선 뉴플러스(백색)80 100p → 4.05mm. 전부 v2·별칭 해석 정상.
- 골든 스펙 잠금: 10항목 ÷2 정합 + 모달 라이브값 파리티 + 소수 4자리 보존.

## 2. 미회신 지종의 현재 서버 동작 (참고 — 귀측 계측 해석용)

- 여전히 미회신: 양장 모조120·뉴플러스100(백/미) / 무선 아트지80·250·300·스노우지80·250·300.
- 이들은 404가 아니라 대부분 **v1 폴백**으로 응답된다(반대편 표의 행이 별칭으로 해석돼 legacy 선형식 적용 — 예: 무선 아트지250 → 양장행 0.235/장 기반 v1). 귀측 validate.js의 `formulaVersion !== 'v2'` warn이 정확히 이 케이스들을 잡는다 — **v1 응답 = 해당 binding용 실측 두께 미보유 신호**로 읽으면 된다. caliper 확보되는 대로 동일 절차(귀측 회신→서버 시드→모달 동기)로 좁혀가자.
