# 포토북 frame-fill 자동배치 — 실기기 E2E 체크리스트 (트랙 D-a, 2026-07-15)

> 정본 근거: RESUME_PROMPT_2026-07-02.md:104 "실 템플릿셋 브라우저 E2E는 잔여". 엔진·UI·입력확장·통합테스트 38건은 c4-2(3b42901) 기머지 — 이 문서는 **코드 0 검증 마감**용.
> 세션이 대신 못 하는 이유: admin 로그인(자격증명 입력)·프로덕션 세션/업로드 생성이 수반됨.

## 준비
1. admin(https://admin.papascompany.co.kr)에서 **사진틀(frame) 포함 포토북 템플릿셋** 1개 준비(기존 셋 있으면 재사용). 모든 페이지에 빈 frame 2개+ 배치된 셋 권장.
2. 테스트 사진 6~10장: EXIF 촬영일시 있는 것/없는 것 혼합 + 저해상도 1장(장변 800px 이하 — 150dpi 경고 트리거용) + 세로/가로 혼합.

## 시나리오 A — '내 업로드' 경로 (데스크톱 + 모바일 실기기 각 1회)
1. 편집기에서 해당 포토북 셋으로 새 세션 → 사진 패널에 사진 업로드.
2. **'사진 자동편집' 버튼이 노출되는가?** (조건: 빈 frame 존재 && 사진>0 — 런타임 판정)
3. 정렬 모드 4종(촬영일/파일명/위치/랜덤) 각각 실행:
   - [ ] 사진이 빈 frame들에 순서대로 채워짐(레이아웃 생성 아님 — 슬롯 채움)
   - [ ] EXIF 있는 사진이 촬영일 순으로 정렬(없는 사진은 폴백 체인: DateTaken→DateAdded→FileName)
   - [ ] 저해상도 사진에 경고 표출(effectiveDpi < 150)
   - [ ] 결과가 편집 가능(잠금 아님 — 프레임 내 사진 이동/스왑 가능)
4. 저장 → 재진입 → [ ] 채움 상태 그대로 복원(라운드트립).

## 시나리오 B — 외부주입 경로 (bookmoa-mobile 임베드)
1. bookmoa-mobile 플로우에서 사진 주입 후 같은 셋 진입 → 자동편집 실행.
2. [ ] 혼합 입력(주입+내 업로드)에서도 정렬·채움 정상. (주의: uploadedAt 시맨틱이 경로별로 다름 — takenAt 우선이라 통상 무영향, SKILL.md 함정 3 참조)

## 시나리오 C — 출력 확인
1. 자동편집 결과로 편집완료 → PDF 생성 → [ ] 프레임 마스킹/사진 배치가 편집기 화면과 일치(스킬 함정: EXIF rotate 경로).
